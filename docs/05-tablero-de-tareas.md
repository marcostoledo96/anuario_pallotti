# Tablero mínimo: Por hacer → En marcha → En revisión → Listo

No crear un sistema complejo de gestión. La persona docente puede copiar este tablero a GitHub Issues o Canva; los alumnos solo necesitan ver las tarjetas de su equipo.

## Antes del encuentro 1 · docente

- [ ] Validar uso de Antigravity con cuentas supervisadas, PCs y perfiles necesarios.
- [ ] Confirmar que el kit abre desde la sala y que hay Internet para referencias.
- [ ] Crear carpeta privada del colegio y asignar permisos mínimos.
- [ ] Pedir a dirección autorización del proyecto y procedimiento de fotos/textos (no necesariamente aprobado antes de clase 1; sí antes de publicar).
- [ ] Probar `materiales-aula/presentacion-clase-1.html` y `referencias-para-votar.html`.
- [ ] Imprimir fichas o llevar plantillas digitales.

## Encuentro 1 · los cuatro equipos

- [ ] Repartir roles; cambiar en la siguiente clase.
- [ ] Ver distintas webs reales y hablar de sus decisiones visuales.
- [ ] Elegir **UNA referencia de estilo por equipo** y justificar dos elementos concretos.
- [ ] Escribir **UN prompt** con sus palabras.
- [ ] Revisar una salida (si alcanza el tiempo) y proponer al menos 1 corrección.
- [ ] Entregar ficha al docente, guardada en soporte institucional.

## Entre encuentros 1 y 2 · docente

- [ ] Reunir las 4 propuestas y conducir la votación de identidad común.
- [ ] Registrar nombre provisional, paleta y patrones de interfaz.
- [ ] Revisar prompts para evitar datos personales y cambios fuera de carpeta.

## Encuentro 2 · por equipo

- [ ] Crear prototipo de su sección con IA, solo en carpeta asignada.
- [ ] Comparar con la propuesta visual votada.
- [ ] Registrar feedback 2–2–1 y una iteración.
- [ ] Guardar en almacenamiento docente y repositorio, sin fotos reales.

## Encuentro 3 · por equipo

- [ ] Incorporar contenido revisado, o mantener DEMO si falta autorización.
- [ ] Corregir una mejora prioritaria.
- [ ] Revisar PC, móvil y contenido.
- [ ] Registrar estado del equipo como «entregado».

## Encuentro 4 · todos + docente

- [ ] Revisar web única y cuatro anclas.
- [ ] Probar galería lightbox (abrir, cerrar, Escape).
- [ ] Confirmar identidad común y créditos de equipos.
- [ ] Resolver máximo 3 problemas prioritarios por equipo.
- [ ] Presentar decisiones creativas, no código.

## Publicación · solo docente + institución

- [ ] Confirmar autorización y revisión de cada pieza real.
- [ ] Quitar DEMO del sitio público definitivo o mantenerlo sin identificación si hay permiso institucional.
- [ ] Comprobar que previews públicos anteriores no contengan datos personales.
- [ ] Publicar y verificar ruta de baja/corrección.
